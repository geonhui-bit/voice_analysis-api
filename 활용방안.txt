1. 사용 모델 및 역할
================================================================================

파이프라인 흐름:
  음성 업로드 → ① STT+화자분리 → ② 운율분석 → ③ 가드레일 → ④ LLM 감정분석 → JSON 응답
  (②③은 규칙·신호처리, ④는 대화·감정 해석)


────────────────────────────────────────
① STT (음성 → 텍스트)
────────────────────────────────────────
모델/엔진:
  - HuggingFace transformers Whisper
  - .env: WHISPERX_MODEL=large-v3-turbo, WHISPERX_LANGUAGE=ko
  - (GB10 호환: faster-whisper/CTranslate2 대신 transformers 경로 사용)

역할:
  - 녹음을 시간 구간별 텍스트로 변환
  - 후처리: stt_cleanup (환각·반복·무음·오타·분할·화자혼합분리 등)

출력:
  - transcript_plain, transcript_labeled, segments[]


────────────────────────────────────────
② 화자 분리 (누가 말했는지)
────────────────────────────────────────
모델/엔진:
  - pyannote.audio (WhisperX 연동, HF_AUTH_TOKEN 필요)

역할:
  - 세그먼트에 SPEAKER_00, SPEAKER_01, UNKNOWN 등 화자 ID 부여
  - guard_filter가 역할 추론: 매니저 / 시니어 / 동거인 / 미확인

출력:
  - speaker_roles, speaker_profiles, transcript_enriched ([매니저] 등)


────────────────────────────────────────
③ 운율·목소리 분석 (높낮이·에너지·말속도)  ← 핵심 보조 채널
────────────────────────────────────────
모델/엔진:
  - 피치(F0): torchcrepe (model='tiny', GPU)
  - 에너지: librosa RMS (CPU)
  - 말속도: librosa onset detection (CPU)

역할:
  - 세그먼트마다: pitch_mean(Hz), pitch_std, energy, speech_rate
  - 화자별 baseline(중앙값) 대비 상대값: pitch_vs_baseline_pct 등
  - 급변 감지: 피치 ±25%, 에너지 ±40% 이상 변화 → sudden_change, change_hint
  - 화자별 요약: sudden_change_count, voice_description

출력:
  - prosody_data (화자별), segment_prosody (세그먼트별)
  - prosody_transcript (|운율: 피치=…| 인라인 태그)
  - analysis_meta (LLM 입력용 운율 요약)

※ ML 감정 분류기(emotion_analyzer)는 현재 미사용 (emotion_data={}).
  감정·톤·분위기 해석은 ④ LLM이 담당.


────────────────────────────────────────
④ 가드레일 (규칙 기반 위험·이상 신호)
────────────────────────────────────────
엔진: guard_filter.py (딥러닝 모델 아님, 규칙·키워드·운율 임계값)

역할:
  - 키워드: 통증·폭언·낙상·사망 등 (문맥 필터: 과거 서사·가정법 제외)
  - 운율: 고성 가능성, 운율 급변 다발 (화자당 ≥7회, PROSODY_SUDDEN_DANGER_MIN)
  - danger_flags ↔ danger_details 일치

출력:
  - danger_detection { detected, flags, details }


────────────────────────────────────────
⑤ LLM (감정·톤·분위기 분석 / 선택 시 보고서)
────────────────────────────────────────
모델/서버:
  - Gemma-4-31B-it-AWQ-4bit (compressed-tensors, ~20GB)
  - vLLM Docker: gemma4-31b-vllm, port 2000
  - .env: LLM_BASE_URL, LLM_MODEL=/models/models/gemma-4-31B-it-AWQ-4bit

역할 (기본 llm_mode=emotion):
  - prosody_transcript + analysis_meta + danger_info 를 읽고
  - 화자별 감정·톤, 대화 분위기, 감정 변화 포인트, 특이사항 JSON 생성
  - 보고서(llm_mode=report)는 별도 선택

출력:
  - emotion_analysis, (report 시 summary)

※ vLLM 미기동 시 emotion_analysis.error = "LLM 서버에 연결할 수 없습니다"
  STT·운율·가드는 정상, LLM만 실패.


────────────────────────────────────────
⑥ 인프라·동시 실행
────────────────────────────────────────
  - FastAPI: uvicorn, API_PORT=9002
  - Celery v2: audio_handler_v2 + analysis_pipeline (FastAPI와 동일 후처리)
  - GPU: STT·화자·torchcrepe와 vLLM이 동시에 VRAM 사용 → vLLM 기동 후
    긴 STT 분석 중 컨테이너 KV 메모리 부족으로 종료될 수 있음 (주의)

2. 활용 방안

────────────────────────────────────────
2-1. 서비스 목표 (역할 분담)
────────────────────────────────────────

| 채널              | 담당              | 잘 잡는 것                    | 보완이 필요한 것              |
|-------------------|-------------------|-------------------------------|-------------------------------|
| 말 내용 (STT·가드·LLM) | Whisper + 규칙 + Gemma | 통증·식사·위험 키워드, 대화 요약 | "괜찮아요"만 하는 날          |
| 목소리·운율       | torchcrepe+librosa | 평소 대비 피치·에너지·급변     | 말 내용만으로는 안 보이는 컨디션 |

핵심 가치:
  - "말은 괜찮아도 목소리·톤이 평소와 다를 수 있다" → 운율·이력이 텍스트를 보완
  - 보고서·감정 문장은 LLM이 알아서 생성; 목소리 쪽은 신호·이상탐지에 집중


────────────────────────────────────────
2-2. 방문 주기에 맞춘 개인 목소리 프로필 (추천 로드맵)
────────────────────────────────────────

운영 가정:
  - 대상자(시니어)당 주 1~2회 방문, 수개월간 반복
  - 담당 매니저가 동일하거나 가끔 교체됨

아이디어:
  - "한 번만 baseline"이 아니라 (어르신, 매니저)별로 방문마다 prosody 지표를 누적
  - 다음 방문 시 "최근 4~8주 분포" 대비 오늘 이탈 여부로 이상 탐지

방문 1회마다 저장할 요약 (JSON prosody_data에서 추출 가능):
  - visit_date, senior_id, manager_id, processing_id
  - 시니어: baseline_pitch, avg_pitch, avg_energy, speech_rate, sudden_change_count
  - 발화 시간·세그먼트 수 (speaker_profiles)

개인 프로필 (롤링 윈도우, 예: 최근 12회 / 8주):
  - 피치·에너지 중앙값, IQR(사분위 범위)
  - 통상 급변 횟수 범위
  - "프로필 수집 중" (초기 3~5회) → 이후 이상탐지 활성화

다음 방문 이상탐지 예:
  - 오늘 pitch_vs_개인중앙값 -25% 이상 AND 에너지 -40%
  - 오늘 sudden_change_count가 개인 상위 10% 초과
  - 텍스트 danger 없어도 → "평소 대비 목소리 변화" 플래그 (추가 관찰 권고)

구현 난이도:
  - 딥러닝 재학습 불필요; 통계(중앙값, IQR, z-score) + 임계값으로 1차 가능
  - 현재 JSON(segment_prosody, prosody_data)가 feature 저장소 역할

주의:
  - 매니저 교체 시 프로필 구간 분리 또는 2~3회 적응 기간
  - 서서히 나빠지는 컨디션 → 급격한 1일 이탈에 더 가중
  - 감기·목소리 쉼 → 텍스트·맥락과 함께 해석


────────────────────────────────────────
2-3. 실험·데이터 수집 전략
────────────────────────────────────────

회귀 테스트 (동일 음성 3종):
  - ~10분 3인(고추·약), ~40분 2인(통풍), ~52분 2인(허리)
  - 코드 수정·서버 재기동 후 "나아졌는지" 비교용
  - 커밋·릴리스 전 3건 전체 1회 권장

일반화 실험 (다양한 신규 음성 70~80%):
  - 2인 돌봄 / 3인 가족 / 짧은·긴 무음 / 통증·식사·사망 서사 등
  - "이 3개에만 맞춘 튜닝" 방지

음성 유형 라벨 (메타데이터, 사람이 부여):
  - speaker_count: 2 / 3+
  - silence_pattern: short / long (30분+)
  - main_topics: 통풍, 허리, 약복용, 식사 …
  - difficulty: 무음후_화자혼선, UNKNOWN_다수, STT_오타 …
  - gold_issues: 사망_flag_없어야_함, post_silence_mix …

결과 JSON 저장 규칙:
  - 음성파일명 ↔ processing_id ↔ 실험라운드 ↔ git commit 연결
  - ~/다운로드/response_*.json + 실험기록.txt 동기화


────────────────────────────────────────
2-4. 목소리 쪽 학습·라벨링 (선택, 중장기)
────────────────────────────────────────

보고서·감정 문장 LLM 학습은 우선순위 낮음 (Gemma가 담당).

목소리·운율 쪽에서 의미 있는 축적:

(1) 임계값 튜닝 (단기)
  - SUDDEN_PITCH_RATIO, PROSODY_SUDDEN_DANGER_MIN 등
  - 라벨: "이 급변은 주의 필요 O/X"

(2) 개인 시계열 baseline (중기, 2-2와 동일)
  - 방문별 prosody 요약 DB
  - 라벨: "이날 컨디션 나쁨/보통/좋음" (간단 청취 평가)

(3) 세그먼트 분류 (중장기)
  - 입력: segment_prosody feature 벡터
  - 출력: normal / pain_vocal / distress / calm …
  - 라벨: prosody_hyp(자동) + prosody_label_gold(사람 청취)

※ torchcrepe 피치 추출 자체를 재학습할 필요는 거의 없음.
  해석·이상탐지·개인화가 핵심.

================================================================================
3. API·출력 필드 빠른 참조
================================================================================

POST /analyze → 주요 응답 필드:

  transcript_enriched     화자 역할 붙은 전사
  prosody_transcript      운율 인라인 태그 포함 (LLM 입력)
  prosody_data            화자별 운율 종합 (이력 저장 핵심)
  segment_prosody         세그먼트별 운율 (이상탐지·학습 feature)
  speaker_roles           SPEAKER_xx → 매니저/시니어/…
  speaker_profiles        발화 횟수·글자수·sparse
  danger_detection        flags, details
  emotion_analysis        LLM 감정 JSON (vLLM 필요)
  timing                  stt_diarization, prosody, llm_emotion, total
